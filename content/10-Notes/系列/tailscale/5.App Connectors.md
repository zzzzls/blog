将指定域名的流量, 转发到指定服务器, 再由这台服务器作为出口访问互联网

- 相较于 Exit Node, App Connector 最大的优势是: 只代理指定域名, 而不是全量转发

1. 客户端访问 example.com
2. App Connector 参与 DNS 解析, 发现 `104.20.23.154`
3. 自动宣告一条具体路由 `104.20.23.154/32`
4. autoApprovers 自动批准, 其属于 `0.0.0.0/0`
5. 客户端通过 connector 访问这个ip, 其他未匹配的互联网流量仍直连

## 配置步骤

### 1. 在服务器B上启用ip转发

> 尽量类 unix 服务器, windows暂未测试

```bash
sudo tee /etc/sysctl.d/99-tailscale.conf > /dev/null <<'EOF'
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1
EOF

sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
```

检查是否生效, 两项都应返回 1

```bash
sysctl net.ipv4.ip_forward
sysctl net.ipv6.conf.all.forwarding
```

### 2. 定义 connector tag

```json
{
	"tagOwners": {
		"tag:my-connector": [],
	}
}
```

### 3. 定义 app connector

```json
{
	"nodeAttrs": [
	  {
		"target": ["*"],
		"app": {
		  "tailscale.com/app-connectors": [
			{
			  "name": "my-domain-app",
			  "connectors": ["tag:my-connector"],
			  "domains": ["example.com", "*.example.com"]
			}
		  ]
		}
	  }
	]
}
```

- `target`: 哪些 Tailscale 设备获得这项节点能力配置
- `name`: 自定义应用名
- `connectors`: 哪些服务器负责作为流量出口
- `domains`: 域名规则

> `target: ["*"]` 表示这项 App Connector 配置面向所有设备下发, 而 `connectors` 指定服务器 B 负责转发.  
> 但这不等于所有设备都自动获得访问权限, 实际能否通过 connector 访问目标地址, 还受到 Grand / ACL 等限制

### 3. 配置 autoApprovers

> 详见: [8.路由宣告与批准](8.路由宣告与批准.md)

```json
{
	"autoApprovers": {
		"routes": {
		  "0.0.0.0/0": ["tag:my-connector"],
		  "::/0": ["tag:my-connector"]
		}
	  }
}
```

### 4. 配置 Grants

```json

{
	"grants": [
    {
      "src": ["autogroup:member"],
      "dst": ["autogroup:internet"],
      "ip": ["*"]
    },
    {
      "src": ["autogroup:member"],
      "dst": ["tag:my-connector"],
      "ip": ["tcp:53", "udp:53"]
    }
  ],
}
```

- 第一条: **允许 Tailnet 成员通过 Tailscale 提供的路由访问公网目标，不限制协议和端口**
- 第二条: 允许成员访问 Connector 的 DNS 端口

注意: 这两条规则仅仅是允许, 并不代表所有公网流量 / DNS请求 经过 Connector, 具体流量走什么路径, 不由此处决定

### 5. 让某台设备成为 App Connector

执行:

```bash
sudo tailscale up \
  --advertise-connector \
  --advertise-tags=tag:my-connector
```

- `--advertise-connector`：启用应用连接器功能
- `--advertise-tags`：将设备与策略中定义的标签绑定

### 6. 客户端开始使用

- 对于 windows 客户端, 保持 tailscale 连接即可 (*默认启用 Tailscale DNS 和 子网路由接受功能*)
- Linux 客户端需要执行: `sudo tailscale set --accept-routes=true`

## 如何验证是否生效

使用一个公网 IP 查询域名做临时测试，例如 api.ipify.org：
1. 暂时把 api.ipify.org 也加到 App Connector 的 Domains。
2. 在服务器 B 执行 `curl -4 https://api.ipify.org`
3. 在客户端 A 执行 `curl -4 https://api.ipify.org`
4. 比较两个命令返回的公网 IP

如果返回的出口 IP 一致，且与服务器 B 的公网出口一致，就说明这个测试域名的流量已经通过 B 转发。验证完成后可删除测试域名。
